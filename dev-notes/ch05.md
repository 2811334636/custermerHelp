**⑤ LangGraph 探测结论（Task 0，2026-10-21）**

- **结果**：`uv run python -m scripts.probe_langgraph` → 9/9 PASS（脚本 `scripts/probe_langgraph.py`）。版本：langgraph 1.2.16、langgraph-checkpoint-sqlite 3.1.2（连带 checkpoint 4.3.0、aiosqlite 0.22.1），`uv add` 已写入 `pyproject.toml`/`uv.lock`（Task 1 只改注释）。
- **`AsyncSqliteSaver.from_conn_string(path)`**：是 `@asynccontextmanager`，必须 `async with` 用。yield 出的 saver 构造后 `is_setup=False`，**不需要手动 `setup()`**——首次 `aput`/`aget_tuple` 内部自动建表（实测首次运行后 `is_setup=True`；docstring 明说不要直接调）。生命周期按 spec：`async with AsyncSqliteSaver.from_conn_string(...) as cp:` 包住整个应用；连接不关会让进程挂住。
- **`astream(..., stream_mode="custom")`**：事件就是节点内 `get_stream_writer()` 传入的原样 payload（dict），无包装、无元组。
- **`subgraphs=True` 的事件形状**：所有事件统一变成 `(namespace: tuple[str, ...], payload)`；顶层 namespace 为 `()`，子图 namespace 形如 `('subgraph:<uuid>',)`（`<节点名>:<task uuid>`）。子图事件不会额外以裸 payload 出现；消费端要先判 tuple 再解包，`e[1]` 才是 payload。
- **checkpoint 恢复**：同一 `thread_id` 下第二次 `astream(None, config)` 从上次 checkpoint 继续（探测用 `interrupt_after=["step_a"]` 制造断点，second pass 的 step_b 读到上一轮 `counter==1` 与 AIMessage 工具调用）；`await graph.aget_state(config)` 可直接拿持久化 State。
- **`add_messages`**：跨节点返回的 `AIMessage(tool_calls=[...])` 与 `ToolMessage(tool_call_id=...)` 按追加语义合并、顺序保留；AIMessage 的 `id` 保留，tool_calls 规范化为 `{'name','args','id','type':'tool_call'}`；ToolMessage 未给 id 时自动生成 uuid。
- **结论**：与 spec §15 的版本假设一致，无需换方案。后续约束：SSE 适配层按 `(namespace, payload)` 解包并兼容顶层 `()`；等待态跨轮仍由 State 字段承载，不引入 `interrupt`。
